# 프로그램 구조

## 파일별 역할

| 파일 | 역할 |
| --- | --- |
| `main.py` | 진입점. `game.py`의 `QuizGame`을 생성하고 실행한다. |
| `game.py` | `QuizGame`이 퀴즈 목록, 최고 점수, 완료한 라운드 기록을 관리한다. 메뉴와 라운드를 진행하고 필요한 시점에 저장을 요청한다. |
| `quiz.py` | `Quiz`는 문제 본문, 선택지 4개, 1~4의 정수인 정답 번호를 담는다. 문제와 선택지를 표시할 수 있고 입력한 번호의 정답 여부를 판정한다. |
| `record.py` | `answer_points()`가 한 문항의 배점을 계산한다. `RoundRecord`는 한 판의 결과를 담고 기존 최고 점수를 넘었는지 판정한다. |
| `data_control.py` | `state.json`을 UTF-8 JSON으로 읽고 쓰며 스키마를 검증한다. 파일이 없거나 내용이 손상된 경우와 읽기·쓰기 오류를 호출부가 구분할 수 있게 전달한다. |
| `state.json` | 프로젝트 루트에 두며 퀴즈 목록, 최고 점수, 완료한 라운드 기록을 보관한다. |

## 객체지향을 선택한 이유

`Quiz`는 한 문항의 문제, 선택지, 정답 번호를 그 데이터를 사용하는 동작과 함께 둔다. 예를 들어 게임은 `quiz.is_correct(선택번호)`를 호출해 정답 여부를 받는다. 정답 번호를 어떻게 비교할지는 문항 안에서 결정하므로 순서대로 풀기와 무작위 풀기 모두 같은 판정 규칙을 쓴다. 이처럼 호출하는 쪽에서 알아야 할 세부 사항을 줄이는 것이 이 설계에서 얻는 캡슐화의 이점이다.

상태 관리의 차이는 한 판을 끝낼 때 드러난다. `QuizGame.play()`는 풀이 중인 점수를 지역 변수에 누적한다. 마지막 답까지 받은 뒤에만 `RoundRecord`를 만들고, 최고 점수 갱신 여부를 확인하고, 기록을 추가한 뒤 저장을 요청한다. 그래서 첫 판을 0점으로 완주하면 기록이 남고, 중간에 종료하면 이전 기록이 유지된다.

같은 기능을 순수 함수 중심으로 설계하면 이전 상태와 완료 기록을 받아 새 상태를 반환하게 할 수 있다. 이 방식은 파일이나 터미널 없이 입력과 반환값만으로 최고 점수 갱신 규칙을 테스트하기 쉽다. 대신 메뉴를 실행하는 쪽에서 새 상태를 보관하고 다음 조회와 저장에 전달해야 한다. 현재는 여러 메뉴가 공유하는 상태를 `QuizGame`에 두고, 상태가 필요 없는 배점 계산은 순수 함수로 분리했다. 예를 들어 `answer_points(True, True)`는 게임의 이전 기록과 관계없이 항상 3을 반환한다.

## 상태 불러오기와 저장

- 실행할 때 `QuizGame`이 데이터를 한 번 불러온다. 파일이 없으면 선택한 주제의 기본 `Quiz` 5개 이상과 `null`인 최고 점수로 시작한다.
- JSON 구문, 인코딩 또는 스키마가 손상됐으면 안내한 뒤 기본 상태로 시작한다. 그 외 읽기 오류는 안내하고 안전하게 종료한다. 스키마에 맞는 빈 퀴즈 목록은 그대로 사용하며, 출제 또는 목록 조회 시 퀴즈가 없다고 안내한다.
- 퀴즈 등록·삭제를 확정하거나 한 판을 끝낼 때마다 저장한다. 최고 점수가 그대로여도 완료한 판의 기록은 추가한다.
- 저장에 실패하면 사용자에게 알리고 완료된 변경 사항을 메모리에 유지한다. 다음 저장 요청이나 종료 시 저장을 다시 시도한다. 종료 시에도 실패하면 그 결과를 안내한다.

### 데이터 증가에 따른 JSON 저장 비용

루트의 `state.json` 한 파일에 게임 상태를 담으면 별도의 서버 없이 표준 라이브러리로 읽고 쓸 수 있고, 사람이 열어서 문항과 점수를 확인하기도 쉽다. 이 방식의 비용은 문항 하나를 바꿀 때나 한 판을 더 기록할 때도 **전체 데이터 크기**에 따라 달라진다.

| 시점 | 현재 코드의 동작 | 데이터가 늘어날 때의 영향 |
| --- | --- | --- |
| 게임 시작 | `DataController.load()`가 파일 전체를 읽고 모든 항목을 검증해 `Quiz`와 `RoundRecord` 목록을 만든다. | 첫 메뉴가 뜨기까지 더 오래 걸린다. 변환하는 동안 JSON에서 읽은 딕셔너리와 새 객체 목록이 메모리에 함께 존재한다. |
| 문항 변경·라운드 완료 | `DataController.save()`가 모든 문항과 기록을 `asdict()`로 변환하고 임시 파일에 쓴 뒤 기존 파일을 교체한다. | 변경 한 건에도 모든 항목을 변환하고 다시 쓰므로 저장 대기 시간이 늘어난다. 변환한 딕셔너리 목록을 위한 메모리와 새 파일 한 개를 쓸 디스크 여유 공간도 필요하다. |

기본 문항 14개를 고정하고 풀이 기록 수만 바꿔 임시 파일에서 측정했다. Linux x86_64와 CPython 3.11.13에서 한 번씩 예열한 뒤 읽기·쓰기 각각 5회의 중앙값을 구했다. 메모리는 별도 읽기 1회 동안 `tracemalloc`으로 추적한 파이썬 메모리 할당의 최댓값이다.

| 풀이 기록 | 파일 크기 | 읽기 | 쓰기 | 읽기 중 최대 메모리 |
| ---: | ---: | ---: | ---: | ---: |
| 100건 | 25,233바이트 | 0.3 ms | 1.3 ms | 0.11 MiB |
| 10,000건 | 1,569,633바이트 | 20.6 ms | 88.2 ms | 7.48 MiB |

#### 데이터가 더 늘어날 때의 대응 방안

- **JSON 저장 시 메모리가 부족할 때**는 문항과 기록을 한 건씩 딕셔너리로 변환해 임시 파일에 쓰고, 모두 성공한 뒤 교체할 수 있다. 미션의 JSON 형식을 유지하면서 딕셔너리 목록 전체를 동시에 보관하는 부담을 줄인다. 파일 전체를 쓰는 비용은 남는다.
- **기록 누적으로 시작과 저장이 느려질 때**는 단일 JSON 파일 제약이 없는 후속 버전에서 표준 라이브러리의 `sqlite3`를 쓸 수 있다. 완료 기록 한 건을 추가하고 최고 점수를 갱신하는 작업을 한 트랜잭션으로 묶는다. 점수 화면에서도 최근 기록부터 필요한 만큼 조회할 수 있다.

## 점수 계산

- 맞힌 문제는 5점, 틀린 문제는 0점이다. 힌트를 사용해 맞힌 문제는 3점이다.
- 라운드의 모든 문제를 풀면 합산 점수를 표시한다. 첫 완료 라운드의 점수를 최고 점수로 기록하고, 이후에는 기존 최고 점수보다 높을 때만 갱신한다. 동점이면 기존 기록을 유지한다.
- 첫 라운드가 끝나기 전 점수 확인을 선택하면 기록이 없다고 안내한다. 풀이 도중 종료한 라운드는 최고 점수에 반영하지 않는다.

## state.json

- `quizzes`는 퀴즈 배열이다. 각 퀴즈에는 비어 있지 않은 문자열인 `question`, 비어 있지 않은 문자열 4개의 배열인 `choices`, 그리고 1~4의 정수인 `answer`가 필요하다. `answer`가 1이면 배열의 첫 번째 선택지가 정답이다.
- `best_score`는 0 이상의 정수 또는 `null`이다. `null`은 완료한 라운드가 없음을 의미하고, `0`은 완료한 라운드의 최고 점수가 0점임을 의미한다.
- `records`는 라운드 기록을 완료한 순서대로 담는다. 각 기록에는 플레이 시각, 문항 수, 점수가 있고 새 기록에는 정답 수와 힌트 사용 횟수도 있다. `records`가 없는 이전 저장 파일은 빈 기록 목록으로 읽는다.

아래 예시는 형식을 설명하기 위해 퀴즈 한 개를 담았다.

```json
{
  "quizzes": [
    {
      "question": "파이썬에서 생성한 뒤 요소를 바꿀 수 없는 자료형은?",
      "choices": ["리스트", "딕셔너리", "집합", "튜플"],
      "answer": 4
    }
  ],
  "best_score": null,
  "records": []
}
```

퀴즈 삭제에는 목록에 표시된 번호를 사용한다. 각 퀴즈에는 선택 항목으로 힌트 `hint`, 해설 `explanation`, 등록일 `created_at`을 저장할 수 있다.
